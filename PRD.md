## 1. Что это и зачем

Многоязычный (🇦🇲 hy / 🇬🇧 en / 🇷🇺 ru) AI-ассистент академии для **абитуриентов** и **студентов**.
Отвечает **только по одобренному контенту академии** (RAG): каталог курсов, расписание, политики, FAQ, оплата.
Если не уверен — честно передаёт диалог человеку, а не выдумывает.

**Боль, которую решаем:** одни и те же вопросы каждый день сыплются по email, Instagram, телефону, Slack («когда старт курса», «сколько стоит», «когда мой экзамен», «я оплатил за этот месяц?», «как оформить отмазку»). Сотрудники отвечают вручную, часто после работы; абитуриент без быстрого ответа часто уходит навсегда.

## 2. Границы MVP (что сдаём к сроку)

Делаем **веб-версию** (виджет чата на странице). Telegram/Slack-боты из описания — помечены как «фаза 2», в MVP не входят, но архитектура ядра от канала не зависит (один `/chat` API, каналы — тонкие адаптеры).

### В MVP входит:
1. **Чат-виджет** на сайте, адаптив (телефон/десктоп), светлая/тёмная тема.
2. **Мультиязычность**: автоопределение языка вопроса (hy/ru/en) → ответ на том же языке. Переключатель языка вручную.
3. **RAG-ответы**: ответы строятся только из базы знаний академии (`/knowledge`). Каждый ответ — со ссылкой на источник. Нет данных → «не знаю, передаю человеку».
4. **Два режима:**
   - **Гость/абитуриент** (без входа): программы, цены, требования, расписание, FAQ; **запись на вступительный тест/собеседование** (форма) → создаётся **лид**.
   - **Студент** (демо-вход по коду): свой **график**, **статус оплаты**, **посещаемость**, запрос-**отмазка** (excuse). Данные — из демо-БД (моки реальной структуры).
5. **Human handoff**: если уверенность низкая или вопрос вне базы — кнопка/триггер «передать человеку», диалог с контекстом сохраняется в БД (таблица `handoffs`).
6. **Админ-мини-панель** (1 экран): лиды, хэндоффы, последние диалоги — чтобы на защите показать, что данные реально копятся.

### В MVP НЕ входит (фаза 2):
- Telegram/Slack каналы, интеграция с реальной Navigator CRM и Core Engine API, черновики ответов на email (можно добавить как «бонус-эндпоинт», если останется время), голос, оплата онлайн.

## 3. Пользовательские сценарии (ключевые)

1. **Абитуриент, армянский:** «Ե՞րբ է սկսվում հաջորդ կուրսը և որքա՞ն արժե» → бот отвечает по базе (расписание занятий Пн–Чт 16:00–19:00, Ada Lovelace; условия), предлагает записаться на вступительный тест → форма → лид сохранён.
2. **Абитуриент, русский:** «Какие требования для поступления?» → ответ из политики + ссылка; предложение собеседования.
3. **Студент, вход по коду `DEMO-STUDENT`:** «Когда мой следующий экзамен и оплатил ли я ноябрь?» → бот из демо-БД отдаёт расписание студента + статус оплаты.
4. **Вопрос вне базы:** «Можно ли приносить собаку на занятия?» → бот: «Точно не знаю, передаю координатору» → запись в `handoffs`.
5. **Отмазка:** студент: «Завтра не смогу прийти, семейные обстоятельства» → бот оформляет excuse-запрос (дата, причина) → запись в БД + подтверждение.

## 4. Данные (демо-БД, структура — как у настоящей)

- `students` (id, имя, язык, трек, группа, статус оплаты по месяцам, посещаемость %).
- `schedule` (трек, день недели, время, аудитория, тема).
- `leads` (имя, контакт, интерес, язык, источник=chatbot, дата, текст диалога).
- `handoffs` (session_id, вопрос, язык, причина, статус open/closed, время).
- `excuses` (student_id, дата, причина, статус).
- `kb_docs` — проиндексированная база знаний (чанки + эмбеддинги).

Сид демо-данных — из реального контента академии (см. `/knowledge/README.md`): 1 демо-студент `DEMO-STUDENT` с заполненным профилем.

## 5. RAG — как отвечаем «только по одобренному»

1. Контент академии лежит в `/knowledge/*.md` (курсы, расписание, FAQ, политики, Fellowship).
2. На старте бэкенда — разбивка на чанки + эмбеддинги (Claude/OpenAI embeddings) в память (контента мало — внешняя vector-БД не нужна, cosine-поиск по массиву).
3. На вопрос: эмбеддинг запроса → top-k чанков → в промпт модели как **единственный источник**.
4. Системный промпт жёстко запрещает отвечать вне переданного контекста; при нехватке — отдаёт флаг `handoff:true`.
5. Ответ возвращает `text`, `sources[]`, `lang`, `confidence`, `handoff`.

## 6. Архитектура / стек (предложение)

- **Frontend:** Vite + React + TypeScript, деплой **Netlify**. Делает Claude (Opus). Чистый виджет, без тяжёлых UI-китов.
- **Backend:** Node + Express + TypeScript, деплой **Render**. Делает Gemini (agy). Эндпоинты: `POST /api/chat`, `POST /api/lead`, `POST /api/excuse`, `GET /api/student/:code`, `GET /api/admin/*`.
- **LLM:** Claude API (`claude-*`). Ключ — у владельца (env `ANTHROPIC_API_KEY`). Эмбеддинги — тем же провайдером или `text-embedding` (уточнить ключ).
- **БД:** SQLite (файл) для MVP — проще деплой; структура переносима на Postgres. На Render — persistent disk или Postgres (free), решим при деплое.
- **Общий тип-контракт** `shared/types.ts` — чтобы фронт и бэк не разъехались.
